# 관세청 수출입실적 OpenAPI

관세청(기관코드 `1220000`)이 공공데이터포털로 제공하는 수출입실적(무역통계) API 17개의 명세입니다. 서비스키·URL·에러 같은 포털 공통 규약은 [공통 규약](../README.md)을 먼저 보세요.

포털 공식 명세(`_source/`)와 실 API 호출 결과를 대조해 작성했습니다(실측일 2026-10-02). 둘이 다르면 실측을 따르고, 차이는 각 API 문서의 "함정" 절에 적었습니다.

## 공통 사항

- **출력은 XML 뿐이고 페이지네이션이 없다.** 한 번 호출하면 전체 행이 온다([공통 규약](../README.md#공통-인자)).
- **기간** `strtYymm`·`endYymm` 은 `YYYYMM`, 둘 다 필수. 시작·종료를 포함해 **최대 12개월**이다. `202507~202606` 은 정상, `202506~202606`(13개월)은 `resultCode` 99 `시작과 종료의 조회기간은 1년이내 기간만 가능합니다.` 형식이 틀리면(`2026-01`, `2026.01`) 99 `시작년월 형식이 맞지 않습니다.`
- **금액**은 미국 달러. 수출은 FOB 신고금액, 수입은 CIF 과세가격 기준이다(포털 명세). 단, API 13~17 은 **천 달러** 단위다(아래 표).
- **중량**은 순중량 kg(포털 명세).
- **갱신**은 매월 15일경 전월분까지(포털 명세). 최근월 수치는 이후 바뀔 수 있다.

### 데이터 갱신

2026-10-02 기준으로 **2026.08 까지** 데이터가 있다. `202606~202609` 로 조회하면 06·07·08 세 달만 온다. 아직 집계되지 않은 달은 에러 없이 빠진다(0건이면 `<items/>`).

## 응답 필드 계열

응답 필드 이름이 두 계열로 나뉜다. API 1~12 는 구 계열(`year`, `expDlr` …), API 13~17 은 시도·시군구 계열(`priodTitle`, `expUsdAmt` …)이다. 같은 의미의 필드를 한 행에 놓았다. "확인"은 값이 그대로 같은 것, "규모로 확인"은 두 API 의 총계가 단위를 맞추면 근사하지만 같지는 않은 것(아래 차이 참고), "추정"은 이름·형식만 보고 짝지은 것이다.

| 의미 | 구 계열 (1~12) | 시도·시군구 계열 (13~17) | 대응 근거 |
| --- | --- | --- | --- |
| 기간 | `year` | `priodTitle` | 확인 — 둘 다 총계 행에서 값이 `총계` |
| 수출금액 | `expDlr` (달러) | `expUsdAmt` (천 달러) | 규모로 확인 — API 12 총계 `expDlr` 496114604700 ↔ API 13 총계 `expUsdAmt` 496,113,564 |
| 수입금액 | `impDlr` (달러) | `impUsdAmt` (천 달러) | 규모로 확인 — API 12 총계 358928358296 ↔ API 13 총계 358,802,506 |
| 무역수지 | `balPayments` (달러) | `cmtrBlncAmt` (천 달러) | 규모로 확인 — API 12 총계 137186246404 ↔ API 13 총계 137,311,058 |

위 "규모로 확인" 행의 구 계열 값은 API 12(항구공항별) 총계다. **두 계열의 총계는 반올림 차보다 크게 어긋난다.** 천 달러로 맞춰 보면:

- 수입: API 12 358,928,358,296달러(= 358,928,358 천) ↔ API 13 358,802,506 천. 125,852 천 달러(약 0.035%) 차이.
- 수출: API 13 496,113,564 천은 API 12(496,114,604,700달러)보다 1,041 천, [종류별](종류별.md)(10)·[세관별](세관별.md)(11)(496,114,738,264달러)보다 1,174 천 작다. API 12 와 10·11 도 133,564달러·10건 다르다([항구공항별 함정](항구공항별.md#함정)).
- 무역수지는 124,812 천 달러(약 0.09%), 건수는 수출 5건·수입 33건 다르다.

천 달러 단위라는 결론은 규모(1,000배)로 성립하지만 API 마다 총계가 조금씩 다르다. 집계 기준 차이로 보이고 원인은 확인하지 못했다. **API 사이의 합계가 같다고 가정하는 검증·테스트는 만들지 말 것.** 같은 API 안의 합계(예: [시도별성질별](시도별성질별.md#함정) 대분류 4행 합 = 총계)는 천 단위 반올림 차 안에서 맞는다.

계열 사이의 형식 차이:

| | 구 계열 (1~12) | 시도·시군구 계열 (13~17) |
| --- | --- | --- |
| 숫자 | 순수 정수 문자열 `5244595000` | 공백 패딩 + 천 단위 콤마 문자열 `          -2,218`. 파싱 전에 공백·콤마를 지워야 한다 |
| 금액 단위 | 달러 | 13~15 천 달러(Swagger 는 "달러"라고 적혀 있음). 16 도 천 달러로 규모 확인 — 경기도 시군 6개월 `expUsdAmt` 합계 159,023,487 이 API 13 경기도 159,022,310 과 같은 규모다(1,177 차이로, 186행 반올림 최대치 93 보다 커서 반올림 차만으로는 설명되지 않는다). 17 도 천 달러로 규모 확인 — 경기도 시군 6개월 HS `854232` 수출 합 61,490,109 가 전국 값(API 2, 123,503,381,846달러)의 약 절반이라 천 달러로만 말이 된다(달러면 0.05%). 같은 범위의 시도 단위 값이 없어 합계 일치 검증은 아니다 |
| 기간 값 | `2026.01` (1~9), `202601` (10~12) | **`2026`** (13~15, 연 단위 합산), `2026.01` (16·17, 월별) |
| `totalCount` | 없음 | 16·17 에만 있음(값 = item 수) |

API 13~15 는 월을 하나만 조회해도 그 해의 합산 행 하나로 묶인다. 연도를 걸쳐 조회하면 연도별로 나뉜다(`202507~202606` → `2025` 17행 + `2026` 17행 + 총계).

필드 이름이 같아도 뜻이 API 마다 다른 것이 있다.

- `statCd`: 국가코드(1·3·7·8·9), 대륙코드(4), 경제권코드(5), 수출입종류코드(10).
- `statKor`: 품목명(1·2), 항구·공항명(12, 예 `부산항`·`인천국제공항`).

### 총계 행

일부 API 는 합계 행을 item 으로 섞어 보낸다. **위치가 아니라 기간 필드 값으로 판별한다** — `year` 또는 `priodTitle` 이 `총계` 인 행이다. 위치는 API 마다 다르다.

| 총계 행 위치 | API |
| --- | --- |
| 첫 행 | 1, 13, 14, 15 |
| 마지막 행 | 2, 10, 12 |
| 없음 | 3~9, 11, 16, 17 |

**행을 직접 더할 때도 조심한다.** API 12 는 한 항구가 신고 세관별로 여러 행(2026.01 `KRPUS` 45행)이라 항구별 값은 같은 `year`·`portCd` 끼리 더해야 하고, API 15 는 대분류·중분류가 섞여 와(기본 대분류 4 + 중분류 17) 전부 더하면 중복 합산이다([시도별성질별 함정](시도별성질별.md#함정)).

총계 행의 코드·이름 필드는 값이 `-` 이거나(1·2·10·12) 태그가 아예 없다(13 `sidoNm`, 14 `hsSgn`·`korePrlstNm`, 15 `cdValtValNm`, 12 `cstmSgn`). API 15 총계의 `tmprTpcd` 는 `00000`.

```xml
<item><balPayments>36009904106</balPayments><expDlr>53169766562</expDlr><expWgt>2455910</expWgt><hsCd>-</hsCd><impDlr>17159862456</impDlr><impWgt>1412228</impWgt><statCd>-</statCd><statCdCntnKor1>-</statCdCntnKor1><statKor>-</statKor><year>총계</year></item>
```

## 코드표 함정

- **시도코드 개편(2026.7.1.)** — `시도코드.csv` 비고 원문:

  | 코드 | 시도명 | 비고 |
  | --- | --- | --- |
  | 12 | 전남광주통합특별시 | 2026.7.1. 이후 수출입신고건 통계 조회시 사용 |
  | 29 | 광주광역시 | 2026.7.1.이전 수출입신고건 통계 조회시 사용 |
  | 46 | 전라남도 | 2026.7.1.이전 수출입신고건 통계 조회시 사용 |

  광주·전남은 조회 기간이 2026.7.1. 을 걸치면 코드를 나눠 두 번 불러야 할 수 있다(미실측).
- **같은 인자, 다른 코드표** — `cntnEbkUnfcClsfCd` 는 대륙별(4)과 경제권별(5)이 함께 쓰지만 코드 뜻이 다르다. `10` 이 대륙별에선 `아시아`, 경제권별에선 `EU`.
- **수출·수입이 다른 코드표** — `성질분류코드.csv`·`수출입종류코드.csv` 는 수출 표와 수입 표가 좌우로 나란히 있다(빈 열로 구분). 같은 코드라도 뜻이 다르다(성질 `10000` 은 수출 `1. 식료 및 직접소비재`, 수입 `1. 소비재`). 수출입종류는 수출이 `A`·`B` 같은 영문, 수입이 `11`·`12` 같은 숫자다.
- **성질통합분류코드는 8자리 세세분류만 맞는다** — 15번째 열(`관세청 신성질별 분류세세분류코드`, 예 `11020101`)을 넣어야 한다. 대·중·소·세분류 코드(`10000000`, `13050000` 등)를 넣으면 에러 없이 0건이다(상위로 묶어 주지 않음).
- **세관구분코드.csv 는 두 표다** — 위쪽 `Y`/`N` 이 인자값이고, 아래쪽 `본부세관,세관별코드,세관별코드명` 표는 본부세관 아래 세관 목록(응답의 `cstm` 값 참고용)이다. 본부세관 열은 묶음의 첫 행에만 있다.
- **앞자리 0** — 품목코드(`0101`)·세관코드(`040`)는 0 으로 시작한다. 숫자로 바꾸지 말고 문자열로 다룬다.
- **항구공항코드는 형식이 섞여 있다** — API 12 응답의 `portCd` 는 대부분 5자리 항만코드(`KRPUS`, 기타항 `ZZZZZ`)나 3자리 공항코드(`ICN`, `GMP`)이고, 세관코드처럼 0 으로 채운 3자리(`010`·`037`·`040`)는 소수다. `cstmSgn` 은 항상 3자리 세관코드다. 그런데 `항구공항코드.csv` 는 세관형 코드의 앞자리 0 을 빼고 `10`·`37`·`40`·`13` 으로 적어 두었다. 응답과 실측 인자는 `010` 이다([항구공항별 함정](항구공항별.md#함정)).
- **경제권은 응답이 코드표보다 많다** — `경제권코드.csv` 는 13개지만, API 5 를 코드 없이 부르면 14개가 온다. 코드표에 없는 `11` `EU28` 이 섞여 있다([경제권별 함정](경제권별.md#함정)). 코드표로 경제권 목록을 고정하지 말 것.
- **국가코드는 대문자** — `us` 는 99 `존재하지 않는 국가코드입니다.`
- **응답 이름과 코드표 이름이 다를 수 있다** — 품목코드 `85` 가 코드표엔 `전기제품` 이지만 API 14 응답의 `korePrlstNm` 은 `전기기기와 그 부분품, 녹음기ㆍ…` 처럼 긴 류 명칭이다. 이름은 응답 값을 쓴다.
- **국가명의 `&`** — 코드표 원문은 `GS,남조지아 & 남샌드위치 군도` 이고, 응답에서는 XML 이스케이프된 `&amp;` 로 온다([공통 규약](../README.md#정상-응답)).
